# Adversary Catalog

A reusable library of adversarial Soroban contracts for negative-path testing at every
cross-contract trust boundary in the Zenith protocol. Added as part of **issue #115 —
Adversarial Counterparty Mock Suite**.

## How to use

Add `zenith-test-adversaries` as a `[dev-dependencies]` entry in any crate that needs
adversarial mocks:

```toml
[dev-dependencies]
test_adversaries = { package = "zenith-test-adversaries", path = "../test_adversaries" }
```

Then register any adversary in a test `Env`:

```rust,ignore
use test_adversaries::tokens::FeeOnTransferToken;
let bad_token = env.register_contract(None, FeeOnTransferToken);
```

Every adversary is a standalone `#[contract]` that mirrors the interface of the real
contract it spoofs. Clients generated by the real crates' `contractimport!` / testutils
work against them transparently.

## Token adversaries (`test_adversaries::tokens`)

| Struct | Issue # | Behaviour | Boundary |
|---|---|---|---|
| `LyingBalanceToken` | 115 | `balance()` always returns `i128::MAX`. Any code that records a deposit by trusting `balance()` instead of measuring the delta will over-credit the depositor. | vault `deposit`, options_market collateral |
| `FeeOnTransferToken` | 115 | Silently deducts 10% on every `transfer`, delivering only 90% of the requested amount to the recipient. | vault `safe_inbound_transfer` delta check |
| `RevertOnTransferToken` | 115 | `transfer()` always panics with `TransferReverted`. Every inbound-transfer attempt fails. | vault `deposit`, options_market `buy_option` / `write_option` atomicity |
| `ReentrantToken` | 115 | On `transfer`, attempts a re-entrant call back into a pre-configured target contract before completing. | options_market reentrancy guard |
| `ZeroBalanceToken` | 115 | `balance()` always returns 0 even after receiving tokens. The measured balance delta is always 0. | vault `safe_inbound_transfer` zero-delta guard |
| `OverflowToken` | 115 | `balance()` returns `i128::MAX`; `transfer()` is a no-op. | options_market / vault arithmetic overflow paths |
| `NoMoveToken` | 264 | `transfer()` returns cleanly but moves nothing (honest balances). | vault `deposit`, streams funding |
| `BlacklistToken` | 264 | `transfer()` reverts when sender or recipient is blacklisted (`set_blacklisted`). | vault `withdraw`, streams `withdraw` / `cancel` |

## Oracle adversaries (`test_adversaries::oracle`)

| Struct | Issue # | Behaviour | Boundary |
|---|---|---|---|
| `AlwaysNoneOracle` | 115 | `get_price()` always returns `None` — no price ever available. | `options_market::set_settlement_price_from_oracle`, oracle_adapter fallback |
| `ExtremeHighOracle` | 115 | `get_price()` returns `i128::MAX` — maximum possible price. | Settlement payout overflow arithmetic |
| `ExtremeLowOracle` | 115 | `get_price()` returns `1` — minimum non-zero price. | Put-option payout bounds |
| `RevertingOracle` | 115 | `get_price()` always panics. | `set_settlement_price_from_oracle` atomicity |
| `StaleOracle` | 115 | Returns a price with a timestamp of 0 (always stale). | Staleness guard bypass |
| `NegativePriceOracle` | 115 | `get_price()` returns `-1`. Bypasses oracle-side `InvalidPrice` guard; must be caught by the consumer. | `set_settlement_price_from_oracle` sign validation, oracle_adapter |

## Vault adversaries (`test_adversaries::vault`)

| Struct | Issue # | Behaviour | Boundary |
|---|---|---|---|
| `NoOpVault` | 115 | `deposit` and `withdraw` are no-ops; always returns 0 deposited. | `options_market::escrow_series_to_vault` return-value check |
| `WrongBalanceVault` | 115 | `balance_of()` returns 2× the real balance. | Consumers that trust `balance_of` to authorise withdrawals |
| `RevertOnWithdrawVault` | 115 | `deposit` works; `withdraw` always panics. | `claim_refund_from_vault` atomicity — position must not be marked refunded |
| `DrainVault` | 115 | `withdraw` has no escrow-cap check; allows withdrawing more than deposited (ledger goes negative). | Demonstrates vault invariant violation |

## Multisig adversaries (`test_adversaries::multisig`)

| Struct | Issue # | Behaviour | Boundary |
|---|---|---|---|
| `AlwaysApproveMultisig` | 115 | `is_executable()` always returns `true`. Any action is immediately "approved" with no quorum. | Every `_via_multisig` entrypoint — must validate multisig address, not trust any contract |
| `NeverApproveMultisig` | 115 | `is_executable()` always returns `false`. No action ever proceeds. | Confirms `_via_multisig` paths propagate `Unauthorized` |
| `SingleSignerMultisig` | 115 | 1-of-1 threshold. Fine-grained: `set_action_approved(action_id, bool)` controls per-action approval. | Positive-path cross-contract multisig tests |
| `ExpiredApprovalMultisig` | 115 | `is_executable()` always returns `false` (treats every approval as expired, `approval_ttl = 1s`). | Confirms stale approvals are not cached across ledgers |
| `ReferenceMultisig` | 172 | **Not an adversary.** Honest M-of-N over `u64` action ids: `approve(signer, action_id)`, `is_executable()` true once `threshold` signers approved, zero delay for every class. Stands in for the real `multisig`, whose `BytesN<32>` ids and missing `is_executable` (#150) don't match what `zenith-common` calls. | Positive-path `_via_multisig` tests in options_market and price_oracle |

## Tests by crate

Each crate adds a `src/test_adversaries.rs` file that declares one negative test per
cross-contract call site. Tests that expose an **open vulnerability** are
`#[ignore]`'d with the issue title so they are visible in CI output and un-ignored by
the fix PRs.

| Crate | Test file | Cross-contract boundaries covered |
|---|---|---|
| `options_market` | `src/test_adversaries.rs` | Oracle (`set_settlement_price_from_oracle`), Vault (`escrow_series_to_vault`, `claim_refund_from_vault`), Multisig (all `_via_multisig`), Token (collateral / premium) |
| `price_oracle` | `src/test_adversaries.rs` | Multisig (all `_via_multisig`), Oracle-adapter (both sources) |
| `vault` | `src/test_adversaries.rs` | Token (`safe_inbound_transfer` delta-check), Multisig (all `_via_multisig`) |
